The type stayed the same.
The declared meaning changed.

This locally reproduced example uses the unmodified Stasrift 1.0.1 release. It shows a specific check others can repeat.

One timestamp, two meanings

Field: occurred_at     Type: timestamp
Old declaration:      event_time
New declaration:      processing_time

The simple name-and-type baseline sees no structural change. Stasrift returns INCOMPATIBLE because the declared time axis changed. These declarations were supplied explicitly; the demonstration does not prove that an implementation follows them.

The limits are part of the result

UNCHANGED is not a certificate of correctness. Physical-type-only changes are outside this semantic diff. Empty contracts are accepted. Meaning that is missing or wrongly declared is not made true by a passing check.

This is a small source-based run on Windows with Python 3.12.14 and PyYAML 6.0.3. It is not the full release test suite, a performance benchmark, customer validation or independent endorsement.
