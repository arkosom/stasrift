Stasrift 1.0.1

Structure stayed compatible.
Meaning did not.

Stasrift checks whether declared data meaning changed across versions, even when the schema still passes.

Local CLI · No server · No accounts · Human-reviewed

Try the CLI See the proof 
$ stasrift diff --old v1.yaml --new v2.yaml

INCOMPATIBLE

occurred_at.time_axis
{event_time} → {processing_time}

Reason
Same timestamp shape. Different declared meaning.
The proof

A schema can pass while meaning breaks.

How it works

Local evidence. Human decisions. Explicit compatibility.

1

Scan

Read local SQL, contracts, dbt refs, and documentation.

2

Suggest

Produce deterministic suggestions, questions, or conflicts.

3

Review

A human confirms, edits, or skips. Suggestions never write automatically.

4

Diff

Return UNCHANGED, NARROWED, WIDENED, or INCOMPATIBLE.

Install

Try Stasrift in 5 minutes.

Install v1.0.1, compare two tiny contracts, then try your own repository. Follow the five-minute guide for environment setup, sample files, and expected results.

$ python -m pip install ./stasrift-1.0.1-py3-none-any.whl
$ stasrift --version
stasrift 1.0.1

Requires Python 3.10 or newer. Download the v1.0.1 wheel from GitHub, then run the install command from your download folder. Stasrift is not yet published to PyPI.

v1.0.1 rejects conflicting duplicate fields and unsupported semantic keys. Validate existing contracts before upgrading. Migration guidance and known limitations · SHA256 checksums

Origin

Inspired by J = 0.

Stasrift grew from the Jameson Zero Condition: the idea that “unchanged” only has meaning relative to what is being observed and compared.

The software does not claim new science. It turns that discipline into a practical question for data systems: unchanged according to what?
